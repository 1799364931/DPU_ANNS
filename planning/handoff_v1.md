## 已确认的暂停位置
1. 完整完成上一轮候选合并和截断。
2. 从有序候选集中选择距离最近的未扩展节点。
3. 若首次满足 rank >= ceil(ef*w)，冻结预测簇。
4. 在给该节点设置 expanded 标志、增加扩展计数以及读取邻接表之前，生成交接快照。
5. Host 停止推进该查询，DPU 校验并恢复后，从同一节点开始扩展。

该触发节点仍计入收敛阶段；快照中此前扩展次数不包含该节点。DPU 必须携带已触发标志，避免重复预测。若搜索结束前从未触发，Host 正常完成并返回结果。

## 交接内容
| 内容 | 必须保留的语义 | 表示建议 |
| --- | --- | --- |
| 查询与参数 | 原始 query、维度、距离模式、ef、top-k、总扩展上限 | 固定宽度字段；记录数据集/图/PQ 版本或标识 |
| 候选集 | 当前实际长度、完整有序候选、节点 ID、距离、expanded 标志 | 按原顺序保存；不重算已有距离 |
| visited | 当前查询到此时所有已发现节点，包括已被截出候选集的节点 | 精确集合；可用 bitmap 或 ID 列表；编码尚未选定 |
| PQ 查询表 | Host 已生成的 32×256 个 float 距离表 | 传输现有表，避免恢复时不必要的重算差异 |
| 进度 | 已完成扩展次数、已经触发收敛、触发节点 ID/位置 | 保留全查询扩展预算；恢复时检查触发节点仍为首个未扩展候选 |
| 预测信息 | 触发时冻结的簇 ID 集合 | 用于预取；不决定哪些节点允许继续扩展 |

若要求与 predict 的细分统计完全一致，另需传递 discoveredAfterTrigger 等统计状态；这不是完成正确搜索的必要条件。

visited 是“已发现”而非“已扩展”：predict 在读取邻居并首次发现时立即标记，之后即使候选被截掉也不会清除。只传候选集或已扩展节点会改变搜索。

交接保存当前查询的逻辑状态，但不强制重编码：允许直接搬运双方约定的数组、位图或 epoch 表及其所需元数据。接收端不得直接解引用发送进程的本地指针，也不能把 STL 对象的原始内存当作可跨进程恢复的内容。候选集与 visited 可以共享一块连续存储；表示、布局和传输次数留待后续决定。

## 建议的数据归属
- Host 保有全库邻接表、PQ 编码及全精度向量。
- DPU 保有当前查询、候选集、visited、PQ 查询表和本查询获取的数据。
- 用户已确定全库 PQ 编码常驻 SoC；初始化就绪后开始接收查询。PQ 查询表按查询在交接时搬运，全精度向量仅按需读取。
- DPU 最终对保留候选读取全精度向量并重排；原始 query 因此也需交接。
- 预测未命中必须仍可按需获取数据，保证预测只影响搬运而不裁剪搜索。

## 生命周期与验证建议
- 同一时刻仅一端推进查询；Host 构造完成后冻结快照。
- DPU 校验并恢复完整状态后才继续执行；完成或失败均有明确结果。
- Host 在对应传输和查询生命周期结束前保留被引用内存。具体完成通知与内存可见性由后续传输协议定义。
- 第一轮软件验证：同一平台、同样距离实现与排序规则，比对完整搜索与交接搜索的扩展节点序列、最终候选、top-k、终止原因；搜索不得因为访问时延而改变候选合并顺序。
- 覆盖未触发、空预测窗口、预测完全未命中、已见但被淘汰节点再次出现、剩余扩展预算耗尽。
- 跨 x86/Arm 的浮点误差与近等距排序单独制定验收，不承诺硬件间逐位一致。

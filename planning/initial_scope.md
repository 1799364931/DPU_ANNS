最新已确认需求见 v1_decisions.md；包含实际预测簇预取、独立的 DMA 读取策略入口、定长图布局与 SoC 常驻 PQ 编码。

## 建议的第一条闭环
Host 执行 PQ 图搜索 → 触发收敛 → 冻结预测簇并生成交接状态 → DPU worker 恢复搜索 → 获取所需邻接表与 PQ 编码 → FP32 重排序 → 返回 top-k。

第一阶段仅支持一个在途查询、一个 worker。预测仍沿用 predict 当前窗口语义。缓存复用和多查询并发逐步追加。

## 模块职责草案
- 搜索核心：候选集、visited、距离计算、收敛判定、暂停与恢复。
- 数据访问：邻接表、PQ 编码、全精度向量的请求与完成。
- Host/DPU 服务：请求提交、状态编码、worker 驱动、结果回传。
- 后端：本机软件后端，以及使用真实 SDK 的 DOCA 后端。

搜索核心不持有 DOCA 设备句柄。跨端协议使用固定宽度字段、节点 ID 和偏移，不能传递进程内指针或 STL 对象布局。具体接口后续讨论。

## 无设备阶段的验收层次
1. 本机：软件后端运行完整逻辑，对比不中断基线与交接续搜结果；覆盖状态恢复、缺失数据和失败处理。
2. SDK：用真实头文件及库编译、链接 Host 程序与 AArch64 DPU 程序。仅编译软件后端不足以完成这一项。
3. 真机阶段：验证设备发现、内存注册/导出/导入、任务完成、通信可达性、资源释放和性能；当前条件无法完成。

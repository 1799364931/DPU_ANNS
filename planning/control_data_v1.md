# 第四轮讨论：控制面、数据面与簇生命周期

## 用户确定的方向
- 控制面与数据面分离。
- 用户后续确定 v1 采用消息通道（DOCA Comch 方向），共享环后置。
- 搜索数据读取由 SoC 发起单边访问，避免每次取数都需要 Host 软件处理请求。
- 预留 SoC → Host 通信接口，为后续簇复用与驱逐提供状态反馈。
- 当前仍只规划，不编写代码。

## 最小控制面建议
逻辑上定义两个方向，不要求立即选择其物理实现：
- Host → SoC：提交查询；未来可增加缓存管理命令。
- SoC → Host：查询完成/失败；未来可增加簇引用释放和驱逐完成事件。

v1 用消息通道承载两个方向。SoC → Host 完成与未来簇事件可复用一个通道。v1 只要求查询提交与完成/失败可用；簇管理仅预留消息扩展位置。

任务描述符只包含查询标识、交接数据的区域标识/偏移/长度及必要参数。不把所有搜索状态直接嵌入队列槽。区域描述需要在初始化时通过相应传输机制建立，不能把 Host 本地指针当作 SoC 可直接解引用的地址。

逻辑分离不要求采用不同物理链路。跨端环的发布、消费和可见性必须按后续所选传输后端定义；不能以普通本机共享内存原子操作替代其验证。

## 数据面建议
- Host 在初始化时暴露允许访问的数据区域，并保持其生命周期。
- Host 在收敛点准备并冻结交接数据，然后发布描述符。
- SoC 根据描述符主动读取交接数据，随后主动读取所需邻接表、PQ 编码和全精度向量。
- 预测簇作为批量预取依据，普通缺失数据走按需读取路径；不需要逐节点请求 Host 软件提供数据。
- 用户后续确认 v1 所有数据读取先实现 DMA；交接/预取、缺失补读和重排取向量保持独立策略选择，未来可分别替换为其他单边访问方式。
- 单边访问不等于无需初始化、注册或权限建立；这些归初始化流程，不放入逐节点控制消息。

## v1 单查询生命周期建议
1. Host 在已确认的边界暂停，准备交接区。
2. Host 发布查询描述符；SoC 接收。
3. SoC 读取完整交接状态后恢复查询，Host 不继续推进同一查询。
4. SoC 继续扩展，按需读取数据并完成重排序。
5. 结果就绪且相关在途访问已完成/安全终止后，SoC 发布完成或失败事件。
6. Host 收割事件并回收本次交接资源。队列槽已被消费不意味着交接数据已可释放。

用户已确定结果随完成消息返回，需约束载荷大小。错误事件不自动证明设备已停止访问；必须由后端完成在途访问的清理，之后才能允许释放相关内存。v1 可不增加单独的接收确认事件，以完整查询完成为资源回收边界。

## 为簇管理预留的语义
- 查询释放引用：某查询不再使用某簇。若其他查询或传输仍使用，该簇仍不能驱逐。
- 簇可驱逐：无查询引用、无在途访问需要该缓存副本，可以作为驱逐候选。
- 簇驱逐完成：SoC 已使该缓存副本失效并完成必要清理，该位置可以复用。

“可驱逐”不等于“已驱逐”，引用释放也不必立即删除缓存，以便后续复用。
这里的驱逐针对 DPU 缓存副本，不是删除 Host 上的原始图或向量。

未来可在消息中加入簇 ID 与驻留代次/版本以识别旧事件；当前不设计字段布局或实现缓存状态机。

## 已确认的管理归属
用户确认：Host 管理簇行为，SoC 负责执行。Host 维护用于调度的簇目录和引用记录，并决定驱逐对象；SoC 管理实际驻留内存并反馈释放/驱逐完成。Host 不能仅凭发出命令就认为 SoC 空间已释放。v1 只保留接口，不提前实现完整缓存算法。

## 观测接口（建议）
预留查询标识及紧凑统计的返回方式。Host 记录提交/收割，SoC 记录接收/数据访问/执行；具体指标见 benchmark_v1.md。统计的物理存放和返回方式尚未确定。

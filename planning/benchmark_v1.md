# 第五轮讨论：v1 benchmark 插桩（建议稿）

## 本轮确认与范围
- 用户确认 Host 管理簇行为，SoC 执行并反馈。
- 用户提出需要考虑 benchmark 插桩；以下指标与实现方式仍为建议。
- 当前只规划，不编写或运行代码。

## 目标
回答三个问题：交接后搜索是否正确；端到端时间花在哪里；为了交接与续搜搬运了多少数据。保留后续簇复用、驱逐和并行搬运的观测空间。

## 插桩形态
- 搜索、任务生命周期和数据访问边界记录；不把统计输出散落在距离计算循环里。
- 每条查询各端维护固定大小的普通计数/计时记录，结束后由 Host 按 run ID + query ID 合并。
- 逻辑上独立于候选/visited 策略，物理上可与查询状态共享一块内存。
- 三档建议：关闭；基础计数与阶段计时；针对选定查询的详细追踪。
- 关闭可选插桩仍保留算法所需的扩展预算等控制状态，不改变搜索行为。
- 详细追踪限量，记录是否截断；不逐次打印或写盘，不要求全量事件常驻内存。
- 单查询单 worker 阶段无需为了统计引入共享原子计数或通用监控框架。

## 正确性与工作量
- 结果 ID、Recall@k、是否触发交接、正常终止/扩展上限/失败及错误位置。
- Host/SoC 扩展次数、新发现节点数、visited 命中数、距离计算次数、重排向量数。
- 预测簇数、预测区域节点数、收敛扩展命中数/总数；预测关闭或未触发时记录不可用及原因。
- 若继续使用 predict 中 newly_discovered 等统计，应明确保留相应状态，不能与基本搜索正确性混为一谈。
- 详细追踪可记录扩展节点 ID 和 rank，验证同策略、同平台不中断搜索与交接搜索的一致性。
- 跨平台浮点差异单独验收；不因精确 top-k 结果一致就推断全部状态正确。

## 时间边界
Host 本地单调时钟：
- H0：开始执行查询，在 PQ 查询表构造及搜索之前。
- H1：首次检测到收敛，在冻结预测簇及准备交接区之前。
- H2：查询描述符成功发布。
- H3：Host 已收割成功结果且结果可读；失败则记录失败结束和状态。

派生指标：
- 端到端 H3-H0。
- Host 前段 H1-H0，包含查询准备和收敛前搜索。
- 交接准备/提交 H2-H1，包含预测冻结、打包和提交等待；需要时再拆出队列等待。
- 提交后等待 H3-H2，包含控制传输、SoC 接续执行、结果回传和 Host 收割。

未触发查询不伪造 H1/H2；记录 Host 正常结束时间与端到端时间。

SoC 本地单调时钟（已按全预取就绪后启动修正）：
- D0：收到并接受描述符。
- Ds：交接状态已经读取并恢复。
- Dp：全部预测簇图数据就绪。
- Dstart：实际开始续搜，不早于 Ds 和 Dp。
- Dend：图遍历结束。
- Dr：全精度重排完成。
- Ddone：结果已准备好，相关访问满足回收条件，可发布完成消息。

派生指标：状态装载/恢复 Ds-D0；预取就绪 Dp-D0；启动等待 Dstart-D0；续搜 Dend-Dstart；重排 Dr-Dend；结果准备 Ddone-Dr。
状态装载和预取可能重叠，不直接相加。续搜和重排时间包含各自的缺失/向量读取等待，不能命名为纯计算时间。

不直接相减 Host 与 SoC 时间戳。先在各端计算持续时间，Host 合并统计。端到端与 SoC 阶段存在包含关系，不应全量相加。没有时钟同步或进一步测量前，不把两端差值解释为单向队列或链路延迟。

## 数据访问统计
按访问目的分组：交接状态、邻接表、PQ 编码、FP32 向量；按实际后端区分软件模拟、DMA、RDMA 等。
- 逻辑数据请求数/请求字节数。
- 实际提交传输任务数/字节数、成功/失败任务数；成功完成字节数按可确认的完成量记录。
- DPU 数据访问缓存命中数/未命中数（缓存尚未实现时记不可用，不把缺少插桩写成零命中）。
- 单次提交至观察到完成的时间；详细模式记录样本，基础模式可累计次数和耗时。
- 搜索推进被数据等待阻塞的时长。

逻辑请求可合并或拆分，因此逻辑次数不等于 DMA/RDMA 任务次数；API 传输字节不等于物理 PCIe/网络链路字节。未来任务重叠时，任务耗时之和不等于等待时间，数据等待时间也已包含在相应搜索阶段中。

## 簇指标预留
后续增加：请求簇数、复用簇数、新装载簇数、释放引用事件数、驱逐请求与完成数、缓存驻留字节/峰值、预取字节与实际使用数据量。
Host 记录管理决策与提交，SoC 记录执行及实际驻留；用任务/事件标识关联，不重复计数。v1 不为这些指标提前实现缓存算法。

## 无设备阶段与未来基准
- 本机完整搜索与本机软件后端交接：在相同搜索参数和 visited 策略下对照，验证状态交接及插桩。
- SDK 编译通过：单列构建状态，不视作性能 benchmark。
- 真机具备后再对比 Host 完整搜索与 Host→SoC 卸载；固定数据、图、PQ、参数和策略，记录 Host/DPU 平台与软件版本。
- 软件后端耗时明确标为模拟执行，不用于推断硬件加速比或 DMA/RDMA 性能。
- 单查询在途允许依次运行多条查询和重复试验；报告样本数、预热数、p50/p95/p99、失败/截断/未触发数量。
- 预热、文件加载、设备初始化与内存注册单独记录；稳态每查询计时不混入这些初始化成本，重复查询缓存冷热状态注明。
- 基础插桩开关对照用于量化自身开销，详细追踪运行与正式延迟运行分开。
- 若报告单在途 QPS，应明确它是串行完成速率，不是系统并发吞吐上限。

## 输出建议
逐查询记录 + 运行级汇总与配置；详细 trace 可选。记录数据/图/PQ 标识、查询集合、策略、参数、后端、平台、SDK/编译版本、插桩模式、缓存状态与样本规模。具体文件格式、字段名和目录暂不冻结。

## 下一项议题
先确定哪些属于 v1 基础指标；随后把计时边界、统计返回方式纳入请求/完成事件协议。完整缓存指标与硬件性能测量留待相应能力具备。

## 第六轮需求补充
用户明确 v1 实际预取预测簇、各类读取先采用 DMA，PQ 编码常驻。应增加交接状态就绪、首个扩展邻接表就绪、完整预测簇就绪的 SoC 本地时间，以及首轮等待、预取实际字节与命中读数。PQ 常驻初始化与每查询 LUT 搬运单独计量；SoC 续搜访问 PQ 编码应为本地访问，不计作远程读取。预取、补读、重排策略分别标注，不能只记录一个全局 backend。

## 最小协议确定后的补充
Host 不再逐查询打包整簇图数据，离线重排准备单独计时；每查询仍计预测冻结、状态准备与描述提交。用户确定全部预测簇就绪后续搜，因此记录状态就绪、完整预取就绪及首次扩展时刻，分离启动等待与续搜缺失补读。簇偏移单位和图 ID/数据集 ID 一致性需纳入结果解释。

## 重排编号后的验收口径
搜索 trace 和内部候选使用图 ID，返回结果与 Recall@k 使用数据集 ID。交接一致性对照同一重排图、PQ 布局与图 ID 排序的 Host 完整搜索。旧 predict 原始 ID 的同距决策可能不同，不能把该差异直接归因于交接。基准配置需要标识重排产物及映射版本。

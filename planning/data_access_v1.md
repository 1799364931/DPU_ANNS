# 第三轮讨论：逻辑接口与存储实现（建议稿）

## 用户已确认的原则
- 收敛触发节点尚未扩展时进行交接，由 DPU 从该节点继续。
- 保持可替换的 visited 等策略，底层尽量简单，可用数组。
- 逻辑抽象不要求物理隔离；允许候选集和 visited 位于相邻内存，以便批量交接。
- 复杂布局和优化以后讨论，当前只制定计划，不写代码。

## 语义、存储与传输的边界
1. 搜索语义规定候选排序、选点、扩展、去重和终止行为。
2. 存储实现决定数组、位图、epoch 表或其他表示，是否共享一块内存，以及数据对齐与容量。
3. 交接实现保证接收端能够正确解释并继续使用当前策略的状态。

这些是职责边界，不要求分别分配内存，也不预设继承体系、虚函数、插件注册或运行时策略切换。v1 只需一种简单实现，后续可通过局部替换增加策略。

## visited 契约
- 查询某节点是否已见、将节点记为已见、开始新查询、在交接后恢复该策略的状态。
- 对当前 predict 精确基线，“已见”包含所有已发现节点，即使节点已离开候选集。
- 交接不强制转成节点 ID 列表；允许直接搬运数组、位图或 epoch 表及其解释所需的元数据。
- Host 与 DPU 必须使用兼容的表示/参数，或进行定义明确的转换；不可把不同策略的字节直接互相解释。
- 策略可替换不意味着语义必然相同；未来若采用有碰撞、遗忘或近似去重的策略，应分别评估检索影响。交接正确性首先比较同一策略下的不中断执行与恢复执行。

## 数据访问的最小语义
| 搜索阶段 | 所需数据 | 逻辑输入/输出 |
| --- | --- | --- |
| 扩展节点 | 邻接表 | 节点 ID → 邻居 ID 序列及实际长度 |
| 给新邻居评分 | PQ 编码 | 一组节点 ID → 对应的 PQ32 编码 |
| 最终重排 | 原始向量 | 一组候选 ID → 对应全精度向量 |

距离计算归搜索逻辑；数据访问不隐含重排和候选筛选。上述是能力描述，不是已定 API 签名。

数据访问层负责解析物理布局和数据位置，可选择本地访问、缓存、按需取数或预取命中。传输后端处理字节搬运与完成状态。搜索层不依赖 DOCA 对象，但可保留高效批量访问的实现空间。

## v1 执行顺序建议
- 一个查询、一个 worker；同一时刻仅推进一个节点扩展。
- 先等邻接表可用，再筛掉已见邻居；获取新邻居的 PQ 编码后计算距离，完成合并与截断，再扩展下一节点。
- 此串行语义不要求底层 API 同步：DOCA 后端可以提交异步任务并推进到完成后交还数据。
- 返回数据至少在本轮消费期间有效；不允许下次取数提前覆盖仍在使用的数据。
- 数据失败明确终止并报告查询失败；不能将读取失败伪装成空邻接表或零编码。
- 软件后端按同样的获取与完成边界验证；不能据此证明真实 DMA/RDMA 同步或性能。

## 预测与访问的关系
冻结簇作为预取提示，不是可搜索区域限制。预测未命中仍走普通数据获取路径。后续已确认：v1 实际预取预测簇，PQ 编码常驻 SoC；交接/预取、缺失补读和重排读取各自保留独立策略入口，v1 均采用 DMA。上述“获取 PQ 编码”在 SoC 上对应本地驻留数组访问。见 v1_decisions.md。

## ID 约定（后续已确认）
数据访问入口接受搜索使用的图 ID。邻接表按图 ID 直接定位，PQ 按图 ID 本地访问；全精度向量访问实现内部用 graph_to_dataset 转换后定位 Host 原始向量。转换不渗透进逐邻居搜索循环。

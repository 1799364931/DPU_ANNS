# v1 最小协议与聚类图布局

## 已确认方案
- 控制面采用消息通道；按此前讨论使用 DOCA Comch 方向，不要求 v1 实现跨端共享环。
- 原图按聚类重排存储，同一簇的节点邻接表连续，使用 CSR 风格簇偏移数组说明每簇范围。
- 保持定长节点邻接记录，容量为最大度数，维护数据集 ID ↔ 图 ID 的双向映射；搜索统一使用图 ID。
- 完整交接状态与全部预测簇数据均就绪后才开始续搜。
- top-k 结果随完成消息返回。
- 以上仍是规划，尚未编写系统代码或转换数据。

## 图布局解释与建议
图 ID 同时作为搜索节点编号和重排后的邻接记录序号。簇偏移 cluster_offsets 长度为 C+1，单位建议为节点记录数；区间 [cluster_offsets[c], cluster_offsets[c+1]) 是簇 c 的图 ID 范围。若每条记录步长为 S 字节，则该簇对应 Host 图内存中的 offset=cluster_offsets[c]×S、length=(cluster_offsets[c+1]-cluster_offsets[c])×S。

该数组描述的是簇边界，不替代每条定长邻接记录的有效度数。空簇允许相邻偏移相等。非相邻簇各自连续，不强求所有预测簇合成一次 DMA；单簇很大时可按实际 DMA 能力拆分任务，不改变整体就绪条件。

图转换属于离线准备阶段，一次生成独立 ANNS 产物，不在每次交接时打包，不改写 correct 中归档资产。必须验证映射为合法排列、簇范围覆盖全部节点、记录中的有效邻居及其顺序保持原图语义。

## 已确认的 ID 语义
用户确定：Host 与 SoC 的搜索过程都使用重排后的图 ID，读取原始数据集及返回结果时才映射。
- 图入口、候选集、visited、邻接记录中的邻居编号、扩展 trace 统一为图 ID。
- dataset_to_graph 将原始节点映射至新编号；graph_to_dataset 将新编号映射回原始节点，两者互为逆排列。
- 离线准备同时重排邻接记录，并将每个有效邻居 ID 转换为图 ID，保持原有邻居顺序。
- Host 与 SoC 使用的 PQ 编码均按图 ID 排列，满足 PQ_graph[g] = PQ_original[graph_to_dataset[g]]；仅重排编码行，不重新训练或改变 PQ 码本。
- 原始全精度向量保持数据集顺序。重排取向量时先以 graph_to_dataset 将候选 g 转为原始 ID，再计算 Host 向量位置并 DMA 读取。
- 距离重排期间候选仍用图 ID；选定 top-k 后将结果转换为数据集 ID，随完成消息返回。无交接的 Host 完成路径也同样转换。
- 聚类预测根据图 ID 查簇；原 vector_to_cluster 不可直接用图 ID 索引，需重排其映射或通过簇偏移定位，具体形式后续决定。
- SoC 具备所需反向映射和簇定位元数据，不能每次读取原始向量都请求 Host 软件解释 ID。
- 查询 ID 标识请求，不属于 base 节点编号重排；不把 query ID 与图节点 ID 混用。

建议同距排序统一按图 ID，保持运行时无需回查原始 ID。图重编号可能因此改变与旧 predict 原始编号执行之间的同距取舍，这是布局/编号变化的影响，不能直接认定为交接错误。交接正确性应对照同一重排图和同一排序规则的完整 Host 搜索；离线图等价性则通过双向映射核对边、邻居顺序、PQ 和簇归属。Ground truth 与 Recall@k 使用映射后的数据集 ID 计算。

## 初始化消息与就绪
一次会话初始化完成以下约定：
- 协议/布局版本，数据集、图、聚类、PQ 的一致性标识。
- 节点数、维度、最大度数、记录步长、ID 含义。
- Host 图/向量/交接区的 DMA 访问描述。
- 必需的常驻元数据（簇偏移、ID 映射等）和 SoC PQ 编码已准备好。
- 查询规模、控制消息最大载荷、状态与预测数据缓冲容量可满足 v1 配置。

元数据常驻位置与装载方式后续细化；SoC 不能依赖每次取图都由 Host 软件解析偏移。资源就绪后 SoC 返回 READY，Host 才提交查询。

## 提交消息
建议控制消息包含会话/查询标识、状态区位置与长度，以及协议需要的小型描述。候选/visited/query/LUT/预测簇列表可位于状态区中；预测簇列表较大时不强塞进控制消息。

为了尽早发起预取，可以在提交消息或较小的前导描述中携带可定位预测簇列表的信息。需要先读取描述才能发起后续读取时应计入交接耗时。描述布局尚未固定，不承诺状态与簇物理同时到达。

Host 不再逐查询复制整簇图数据，SoC 根据簇偏移直接 DMA 读取 Host 的重排图区域。交接状态与预取可分别提交；各类传输策略仍独立选择，v1 全部使用 DMA。

## 执行与完成
1. Host 在触发节点扩展前冻结状态并提交。
2. SoC 验证标识、范围和容量，读取完整状态及所有预测簇图数据。
3. 全部成功就绪后恢复搜索。没有预测簇时预取条件视为满足。
4. 扩展节点的邻接表不在预取区时，走独立的 DMA 补读路径。触发节点未必属于预测区域，也按普通缺失处理。
5. 按图 ID 访问常驻 PQ 编码，用本查询 LUT 计算距离并完成图搜索；通过反向映射定位原始向量，以独立 DMA 路径读取后重排。
6. 在相关访问结束后，完成消息返回查询标识、成功/失败状态、已转换为数据集 ID 的 top-k 结果及基础统计。
7. Host 收割并回收本查询资源。v1 不要求跨查询保留簇副本，复用/驱逐只预留接口。

完成载荷需适配实际 Comch 能力。建议初始化时约束 top-k 与基础统计大小；详细 trace 本地保存。失败回报必须保证其承诺可回收的资源已无在途访问。

## 容量与失败建议
完整预取意味着必须有足够空间容纳本查询选定区域及搜索状态。先计算需求，不能装不下就静默丢弃部分预测簇却声称完成预取。v1 建议容量不足时明确拒绝/失败；分批驱逐执行会改变已选定的简单方案，后置讨论。

## 验收补充
- 原图与重排图按数据集 ID 解读后邻居及顺序一致。
- 两份映射互逆；入口、邻接边、PQ 行和簇归属转换正确，原始向量读取及输出 ID 反向转换正确。
- 完整 Host 基线与交接续搜都使用重排图 ID；trace 标明 ID 空间，Recall 按数据集 ID 计算。
- 实际从簇连续区预取图数据，无逐查询整簇重打包。
- 不在全部预测簇完成之前开始扩展，注入乱序完成/失败可验证该条件。
- 预取未覆盖触发节点、空簇/空预测、簇跨多个 DMA 任务、状态或预取失败均有明确行为。
- 结果消息可与查询标识对应，参数超出支持消息大小时明确报告。

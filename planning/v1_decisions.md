# v1 已确认设计（持续更新）

本文件汇总用户已明确的决策；讨论稿中的旧建议如与本文件冲突，以本文件为准。当前只制定计划，不写代码、不安装依赖。

## 目标与边界
- BlueField-2，当前无设备；先实现单查询正确交接的代码与编译目标，真机验证留待设备可用。
- Host 在首次触发收敛、冻结预测簇后，当前节点尚未扩展时交接。
- 候选/visited 等保持策略抽象，底层可用简单数组，也允许共享连续内存。
- 控制面与数据面分离；v1 采用消息通道（沿此前 DOCA Comch 方案），共享环实现后置。
- SoC 主动单边读取搜索数据。
- Host 管理簇的复用、引用与驱逐；SoC 执行并反馈。完整复用/驱逐算法后置。

## 本轮新增的明确要求
- v1 必须真实读取预测簇所对应的图数据，目标是在交接期间预取，尽量与查询状态接近同时就绪，随后缺失补读。不是仅记录簇 ID。
- v1 数据读取统一先实现 DMA，但交接/预取、缺失补读、重排取向量是独立的策略选择点。不能用一个全局后端选择将三类操作永久绑定。
- 交接状态与预测图数据保留不同用途和完成状态；图按聚类离线连续存储，SoC 直接读取预测簇区段，避免逐查询打包整簇。
- 邻接表运行时使用定长布局，槽容量为图最大度数。每条记录需要有效度数或等价边界，padding 不能当邻居。CSR 作为已有输入可转换；不得静默截断超容量节点。
- 全库 PQ 编码常驻 SoC，初始化完成后才接受查询。Host 逼近阶段仍需访问自己的 PQ 编码数据。
- 全精度向量不常驻 SoC，重排时从 Host 读取。
- PQ 查询表按查询产生，仅随交接搬入 SoC；生命周期属于当前查询，不作为跨查询常驻资产。
- 原始 query 随状态交接，供 SoC 重排使用。

## 最小协议与图重排已确认
- 同一簇的定长邻接记录连续存储，CSR 风格偏移数组记录簇范围。
- 搜索内部统一使用图 ID，包括 Host/SoC 的入口、邻接边、候选集、visited 和 PQ 编码索引。
- 保留数据集 ID ↔ 图 ID 双向映射；读取原始全精度向量、返回结果时转回数据集 ID。PQ 编码按新 ID 重排，原始向量保持原数据集布局。
- 完整状态和全部预测簇数据就绪后才续搜，v1 不做按依赖提前启动。
- top-k 结果随完成消息返回。

## CloudLab Host 环境
- 用户申请镜像为 UBUNTU24-64-STD，Host 基线按 Ubuntu 24.04 x86_64 规划。
- DPU 系统由其 BFB 决定，不能从 Host 镜像推断；两端系统版本分别确定。
